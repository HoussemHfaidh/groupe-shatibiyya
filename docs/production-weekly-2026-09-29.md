# Production — 29 septembre 2026

L'accueil élève « أسبوعي » calcule la semaine courante directement depuis les activités PROD existantes. Les validations des semaines précédentes restent historiques. Une confirmation faite pour un camarade apparaît dans le compteur du validateur et complète l'activité du camarade. Le tableau professeur, les activités et le résumé élève se rafraîchissent via les événements Firebase, avec reprise réseau et vérification périodique.

La page professeur expose « حالة الطلاب », les deux tableaux, les corrections administratives, le report des points, les clôtures et le partage/export PNG. Les corrections, décisions, audits et semaines clôturées sont maintenant stockés dans `config/studentStatus` (groupe 1) et `config/groups/group2/studentStatus` (groupe 2). Chaque changement relit la version distante, utilise un ETag et réessaie sur conflit sans écraser les corrections indépendantes. Une sauvegarde échouée reste explicitement en erreur et ne s'affiche pas comme enregistrée.

Les séances de présence utilisées pour calculer la matrice sont copiées dans ce même espace partagé. Les imports et corrections locaux alimentent la matrice ; une file locale conserve les mises à jour de présence si le réseau est indisponible et les réessaie à l'ouverture/actualisation de la matrice. L'éditeur original de présence reste local au navigateur. Les champs sans source fiable restent inconnus et modifiables par le professeur. Aucune sanction ni clôture n'est inventée à partir des anciennes données.

Le renommage فارس المسعدي → فراس المسعدي a été appliqué aux listes, accès, validations, historiques et valeurs par défaut. L'alias de l'ancien nom est conservé pour les sessions existantes. `scripts/release-prod-20260929.cjs` capture d'abord une sauvegarde privée sous `data/`, puis applique uniquement ce renommage avec ETags. Aucune donnée d'essai DEV n'est copiée en PROD. Les chemins de la matrice utilisent les permissions config déjà déployées : aucune extension des règles Firebase.
